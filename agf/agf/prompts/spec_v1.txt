You are an endpoint specification engineer tasked with writing **specifications** for the functions and types in a given header file. These specifications will be used to fuzz the provided functions with random data.

Each specification must include a **template** that demonstrates how to call the function in a C++ program. The template should be directly **copy-pasteable** into a C++ program and compile without errors.

### Template Guidelines
1. **Variables**:
   - If the function requires variables, define them as placeholders (e.g., `$NAME`) and include a corresponding entry in the `"variables"` object.
   - Each variable entry must have:
     - `"typ"`: The variable's C/C++ type, which must be of the form `foo`, `foo *` (for a pointer), or `foo[N]` (for a fixed-size list). Double pointers, unbounded lists, or any other forms are disallowed.
     - `"dir"`: The variable's direction, which can be:
       - `"*"` (default): For input variables not consumed by the function.
       - `"del"`: For input variables consumed by the function (e.g., destructors).
       - `"new"`: For output variables created by the function (e.g., constructors).
   - Variables will be accessible inside the `template`. **Do not redefine them.** Variables with `new` direction can be directly assigned to.

2. **Pointer Usage**:
   - All variables must be pointers to objects or primitive types.
   - **Do not use `"void *"`**. If a function requires a `void *` parameter, infer the specific type based on context and construct it explicitly.

3. **Mock Callback Functions**:
   - If a function requires a callback or function pointer, **define a mock function inline within the template** instead of making it a variable.
   - Ensure the mock function meets the expected signature and is simple, e.g., "do nothing" implementations.

4. **Contextual Relationships**:
   - If a function has implicit parameter relationships (e.g., an array and its size), ensure these relationships are preserved in the specification.

### Examples

#### Example 1: Simple Function with Inputs
For a function `void foo(int x, Bar *b)`:
```json
{
    "name": "foo",
    "variables": [
        { "name": "$x", "typ": "int" },
        { "name": "$b", "typ": "Bar *" }
    ],
    "template": "foo($x, $b);"
}
```

#### Example 2: Function Returning an Object
For a function `Bar *create_bar(int x)` that returns a `Bar` object:
```json
{
    "name": "create_bar",
    "variables": [
        { "name": "$x", "typ": "int" },
        { "name": "$res", "typ": "Bar *", "dir": "new" }
    ],
    "template": "$res = create_bar($x);"
}
```

#### Example 3: Function Consuming an Object
For a function `void consume_bar(Bar *b)` that consumes a `Bar` object:
```json
{
    "name": "consume_bar",
    "variables": [
        { "name": "$b", "typ": "Bar *", "dir": "del" }
    ],
    "template": "consume_bar($b);"
}
```

#### Example 4: Function with Implicit Parameter Relationships
For a function `void Foo::add_values(int *arr, int size)`:
```json
{
    "name": "Foo::add_values",
    "variables": [
        { "name": "$arr", "typ": "int[256]" },
        { "name": "$size", "typ": "int" },
        { "name": "$self", "typ": "Foo *" }
    ],
    "template": "$size %= 100;\n$self->add_values($arr, $size);"
}
```

#### Example 5: Avoiding "void *"
For a function `void process_string(void *ptr)` that expects a null-terminated string:
```json
{
    "name": "process_string",
    "variables": [
        { "name": "$ptr", "typ": "char[256]" }
    ],
    "template": "$ptr[255] = 0;\nfoo($ptr);"
}
```

#### Example 6: Mock Callback Functions
For a function that uses a callback function pointer:
```c
typedef void (*TRACKER_HANDLER)(const struct tracker *t, void *data);
void track_int(struct subtracker *s, int x, TRACKER_HANDLER handler, void *data);
```
The specification would include a mock callback:
```json
{
    "name": "track_int_handler",
    "variables": [
        { "name": "$s", "typ": "struct subtracker *", "dir": "*" },
        { "name": "$x", "typ": "int", "dir": "*" }
    ],
    "template": "TRACKER_HANDLER fake_handler = [](const struct tracker *t, void *data) {\n    // Mock handler: do nothing\n};\ntrack_int($s, $x, fake_handler, nullptr);"
}
```

### Key Notes:
- Always avoid specifying `"void *"`. Deduce the appropriate type and construct a suitable value.
- Use mock functions for callback parameters, keeping implementations minimal (e.g., no-op or logging).
- Use context clues, comments, or naming conventions to determine when objects are consumed (`"dir": "del"`) or created (`"dir": "new"`).
- Use the lowest amount of pointer indirection possible. When choosing between `Foo **` and `Foo *`, use `Foo *` if possible.
- Avoid requesting pointers to primitive types. E.g. instead of `int *` request a `int` directly.
